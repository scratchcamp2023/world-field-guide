METHODOLOGY

Trust needs a standard.

The Field Guide separates “someone said this once” from clues that have clear scope, counterexamples, and source support.

Draft

1. Draft

A proposed clue or guide module. It can be useful, but it has not passed community review.

In review

2. In review

The claim is being tested for geographic scope, repeatability, false positives, and wording.

Verified

3. Verified

The claim has enough evidence and review to be presented as reliable within a stated scope.

Deprecated

4. Deprecated

Coverage, imagery, or evidence changed enough that the old statement should no longer be taught without a warning.

A VERIFIED ENTRY SHOULD ANSWER

Five questions.

  1. What is the clue?Describe the visible feature precisely.
  2. Where does it apply?Country, region, road type, coverage generation, or other limits.
  3. How strong is it?Standalone identifier, supporting clue, or weak contextual signal.
  4. What breaks it?False friends, exceptions, outdated coverage, or lookalikes.
  5. Why should we believe it?Sources, examples, repeated observations, review trail.
IMAGE POLICY

Visuals need attribution.

Reviewed examples only

Do not publish random screenshots with no context. Every image should correspond to a clue claim and survive review.

Record the source

Each visual should carry a source URL, credit, and licence or permission note.

Prefer multiple examples

A clue is more trustworthy when players can compare more than one reviewed example, not just a single standout image.

Seed-data sources

This front-end includes a small seed set so the system can be demonstrated without pretending the database is already complete. The available Japan, Ghana, Colombia, Guatemala, and Taiwan entries are paraphrased from current Plonk It country guides and marked as seed content. A real public launch should add explicit contributor attribution and per-entry evidence histories.
